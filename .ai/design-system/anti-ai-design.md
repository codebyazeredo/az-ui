# Anti-AI Design — AZ UI

## Objetivo

Garantir que os componentes e exemplos da AZ UI tenham aparência de software corporativo desenvolvido por equipes experientes de produto e engenharia.

## Princípios

1. Funcionalidade antes de decoração.
2. Hierarquia antes de efeitos visuais.
3. Consistência antes de criatividade excessiva.
4. Clareza antes de minimalismo artificial.
5. Densidade informacional adequada.
6. Simplicidade visual com personalidade própria.

## Evitar

- Gradientes utilizados apenas para decorar.
- Glassmorphism como padrão.
- Grandes áreas com cores vibrantes.
- Bordas arredondadas excessivas.
- Sombras grandes em todos os elementos.
- Cards dentro de cards sem justificativa.
- Ícones em todos os títulos.
- Badges para informações que não precisam de destaque.
- Animações exageradas.
- Botões com dimensões desnecessariamente grandes.
- Tipografia com títulos gigantes.
- Layouts com espaços vazios artificiais.
- Componentes com aparência de landing page dentro de sistemas administrativos.
- Uso excessivo de emojis.
- Elementos decorativos que não ajudam na operação.

## Priorizar

- Tabelas bem organizadas.
- Formulários compactos e legíveis.
- Cabeçalhos objetivos.
- Barras de ferramentas funcionais.
- Navegação previsível.
- Estados de componentes claros.
- Feedback discreto.
- Bordas sutis.
- Contraste equilibrado.
- Espaçamentos consistentes.
- Tipografia profissional.
- Componentes reutilizáveis.

## Critério de aprovação

Um componente deve parecer natural dentro de um ERP, CRM, TMS, sistema financeiro ou aplicação administrativa profissional.

Não deve parecer um componente de demonstração criado apenas para impressionar visualmente.

A interface deve continuar funcional e agradável depois de várias horas de utilização.
